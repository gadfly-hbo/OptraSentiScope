## 目标与起点

经营者提出目标后，本期用合成来源演练持续取得资料的完整过程；遇到失联、撤权、暂停或服务重启，经营者能看清哪些研究仍在推进、哪些需要等待以及原因。Qoder 把通过验证的版本切换到本轮获准的服务，并给出恢复证据。

产品代码基线是 [PR #2](https://github.com/gadfly-hbo/OptraSentiScope/pull/2) 合入的 `6ec330d`。已有可修订的委托摘要和局部等待、方向级暂停与恢复、定时结束、简报偏好持久化、本地备份校验及重开读回。P01 判断修正、P02 条件经验已有本地合成链证据。本期复用这些能力，保留历史失败及其复验记录。[已有实现与缺口](../openspec/changes/general-v01-completion/results.md#阶段状态) · [合并前补充修复](../openspec/changes/general-v01-completion/results.md#阶段合并前的补充修复)

## 实施顺序与验收

### 1. P03 委托能持续取得获准资料

由 Qoder 在隔离环境准备一个可控的非 Call 合成来源，经正常工作台、来源接收与持久化入口跑通一项委托，再用两个不同授权的委托检验共享采集。让合成来源产生更新、重复页、失联和撤回，保留输入及接收证据。

- [ ] **建立委托。** 从正常入口用一句话建立目标。Agent 自主查取获准背景，整理可修改摘要，只集中询问影响研究的关键缺口。信息齐备即可开始；缺一项口径时，依赖该口径的研究等待，其余继续。经营者能看到当前覆盖、最后成功更新时间、缺口和人工补充入口。（AC01，U01）
- [ ] **发现、订阅和重开。** Agent 在获准目录或来源清单内选择资料并安排订阅或检查。用一条既影响已有研究、又暴露独立问题的来源更新，验证两种结果能同时发生。Host 核权并去重，Agent 判断业务归属；重复页、重复投递和内部产物不反复建单。原件或准确引用与版本、业务时间和获取时间可读回。接收写入失败时游标不前移；在分页中途退出后重开，既无遗漏也无重复影响。原件缺失或版本冲突显示限制或未知。（AC02–AC04，U02–U04）
- [ ] **共享与撤权。** 对同一来源复用采集，分别核验每个委托的当前授权。让来源依次失联、恢复，并撤销一个委托的授权。核对覆盖状态、恢复后的补读、历史索引、缓存及恢复会话的正文遮蔽；另一委托的合法研究照常进行。记录合成事件发生、Host 接收及撤权生效的时间和结果；真实来源的更新与撤权时限留待实际接入验证。（AC08，U09）

### 2. P04 经营者能判断暂停、恢复和结束的实际结果

在 P03 的共享来源与独立委托可用后，验证跨委托和在途任务。差异分析和无需等待来源的后端工作可以提前做。涉及新关键交互，Qoder 先交相对已批准 Demo 的差异和可点击版本；用户确认后实施相关 UI。

- [ ] **暂停与收束。** 至少覆盖一个在途任务、一个子任务和一个无关方向。暂停或结束先阻止受影响的新派发，再核查在途工作是否确实停止；未能确认时展示处理中或 UNKNOWN。默认暂停专属主动采集，“停研究、留采集”按已选范围执行；其他委托获准的共享采集继续。待决事项和真实窗口保留，暂停普通催办。（AC05、AC08，U05、U08、U10）
- [ ] **恢复与结束摘要。** 恢复时说明暂停期间的变化、资料空白、仍有效的资格、继续项和等待项。结束时从实际记录汇总方案、选择、执行、观察、未决原因、失败与未知；迟到结果不复活委托，后续工作可关联新委托。定时恢复或结束、途中失败并重开与手动控制均从正常入口取证。（AC06、AC08，U06、U08–U10）
- [ ] **工作台与提醒。** 同一事项的提醒可合并，不同待决取舍及其窗口仍能准确直达；简报偏好在轮询、保存及重开后可读回。用真实浏览器逐项核对 U01–U12，对受影响交互验证窄屏、键盘及错误状态。U07 验学习与反证的展示；U11 验 Call 后置状态；U12 核对演示和实际运行边界。逐项记录工程证据和仍待用户体验的部分。

### 3. P05 服务可维护、可恢复，运行边界可核实

身份、出口、凭据和计算关闭检查从 P03 首个切片开始。等 P03/P04 的持久化格式稳定后，再做跨版本恢复、长流和目标服务验证。

- [ ] **身份、权限与出口（R02、R03、R05）。** 从工作台入口验证登录身份、企业与委托 owner 的绑定，普通经营者与维护者的权限各自生效。Host 负责解析、轮换和撤回凭据；核验浏览器、工具、子 Agent 和日志的实际可见内容。逐项验证模型输入及历史重放、外部研究与连接器、提醒与导出、日志监控与备份四类出口。对启用路径查允许和拒绝，对关闭路径查无发送，额外会话上传关闭。
- [ ] **恢复与长流（R01、R06）。** 对旧版与本期写入的隔离数据做备份并恢复到新位置，核对 SQLite、原生会话、调度、游标和未决回执；覆盖中途写入失败、异常退出和重开。关闭浏览器后服务仍按授权推进，服务中断时进展页显示最后可核实状态。UNKNOWN 先查现存结果，避免重复副作用。按递增事件量记录累计写入字节，验证随证据体积线性增长、可完整读回且失败现场可追溯。
- [ ] **组件与计算（R03、R04）。** 核对获准的 Harness 与 superagent 精确版本、原锁、实际加载的模块及 peer 身份；在目标平台记录同一候选的运行证据。计算保持 OFF，覆盖主 Agent、子 Agent 及可用工具入口的拒绝行为，核查宿主机没有代为执行或留下产物。启用计算所需的容器或虚拟机、文件／进程／网络／配额／停止的真实隔离验证继续列为未运行。[已批准组件清单](开发依赖采用清单_v0.1.md)
- [ ] **目标服务（R01–R06 分项）。** 在已有本机独立试用实例核验版本、健康、合成来源资格、重启、恢复和经营者工作台。11 月 20 日交付时为本机回环地址 `127.0.0.1:8766`，切换前核对当前进程、监听与独立数据目录。按 R01–R06 分项记录本机证据；企业 Linux、生产 HTTPS 与身份、生产出口、真实计算隔离列为未运行。

### 4. Qoder 交付、切换与产品验收

- [ ] Qoder 对照本清单与原 AC/U/R 交回逐项结果、候选身份和证据。运行统一检查、受影响的原生链、独立浏览器回归和依赖审计。固定候选，安排全新上下文非作者按规格及工程标准复核，修复发现并请其重验。P01/P02 纳入受影响回归。
- [ ] 按授权在工作分支提交和推送，集中一个 PR。核对最终 head 的 CI，squash 合并后核对 main 提交的 CI。切换前记录旧运行版本、配置引用、数据目录、可恢复备份及回退条件；切换后读回实际版本、健康状态、工作台、来源进展和持久数据。失败时按约定回退并核验数据兼容，保留切换后产生的记录。
- [ ] 向用户交回可体验入口，以及「建立委托并接收来源变化 → 暂停、恢复并查看摘要 → 重开后核对进展」的验收路径。每项分别写明通过、失败、未知、未运行或延后，附证据与下一责任人。产品体验由用户确认。P06 Call、真实模型研究质量、经营 POC 和完整 AC07 继续各自记账，本期交付不关闭整首版验收。
