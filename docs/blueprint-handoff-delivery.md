# 蓝图固化与文档交付范围

日期：2026-11-11 · 类型：纯文档交付

## 目标与批准范围

本轮将已确认的阶段安排写入[蓝图 v0.4](OptraSentiScope_产品蓝图讨论稿_v0.4.md)，并交付本 session 已形成的 baseline、蓝图 v0.1–v0.4、原单店 POC 包及确认记录、会员运营立项记录。历史文件保持原文；本轮只新增 v0.4、本文，更新 README 及工程规范／继承记录的必要部分。

用户明确授权 Git 提交、推送远端、CI 适用核对与合并 main，并要求规则直接参考 OptraCall。具体来源及对应规则唯一维护在[工程规范第5节](engineering-workflow.md#5-git-与-ci-的精简节奏)，精确来源与差异见[继承记录](optracall-inheritance.md#gitci-规则再次核对2026-11-11)。

用户在得知现有上游 CI 依赖 npm 产品工程、本项目当前无法直接运行后，明确选择：

> 本轮按纯文档规则合并，CI 记录未建立；产品搭建时复用同款 CI。

本轮不建立工作流，不引入产品依赖；CI 状态为 **未建立／NOT_CONFIGURED**，不记为 PASS。这是本轮批准安排，不是上游已有的文档自动跳过机制，也不扩大后续运行、安装或部署授权。

## 交付验收与执行清单

| 项目 | 可核对的完成条件 |
| --- | --- |
| 阶段安排固化 | v0.4 明确先通用设计、再通用搭建、后具体 POC；基本成功标准及搭建中的工程检查不后置 |
| 场景与历史保全 | baseline、蓝图 v0.1–v0.3、两个场景原记录及原包保持字节；会员运营仍为后续优先、原单店仅保留 |
| 规则核对 | 直接读取固定上游提交；区分原规则、本项目现状及用户本轮 CI 决定 |
| 文档验证 | 核对差异、引用、范围、编码／空白、公开内容、POC manifest 与历史哈希；无产品测试或占位 RED |
| 独立复核 | 全新聚焦上下文、候选全部作者以外的只读复核者，固定文件清单和哈希；发现修复后重验 |
| Git 交付 | 本轮工作分支 `codex/product-blueprint-handoff`、一个 PR、获授权 squash 到 main，核对实际提交及检查状态，再安全快进本地 main |
| 收尾与交接 | 核对工作区、暂存区、未跟踪文件和本地／远端分支；说明被忽略证据；交接引用实际合并身份及本轮 CI 状态 |

上表定义验收条件，不预先声明尚未发生的推送或合并成功。执行中清单、命令输出、独立报告和最终 Git 回执保存在被忽略的 `.local/blueprint-handoff-delivery/`；提交与 PR 身份同时以 Git／GitHub 历史核对。原包既有失败、未知和有限离线结论继续保留。

## 下一 session

用户将新开 session 和新分支，讨论通用产品设计与通用产品搭建。新 session 先读工程入口、规范、本稿和蓝图 v0.4；从产品形态、最小完整闭环及持续委托的完整使用过程开始。具体 POC 业务细节和完整产品验证安排暂缓，历史未决事项不会因此被当作已解决。

交接文件以独立 handoff 提供，引用本仓库既有资料和实际 PR／合并身份，不复制整份蓝图；本轮不自动创建用户的新 session 或新分支，也不提前设计、开发或运行产品。

## 范围限制

本轮没有产品代码、交互实现、依赖安装、真实模型、POC 跑测、真实会员资料、经营动作、服务／设备更新或部署。UI Demo、产品功能测试及构建不适用；文档检查、独立复核、Git 交付、CI、产品验收分别记录。
