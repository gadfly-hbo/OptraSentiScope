# 效果判断保存与准确读回 v0.1

2026-11-17，落实产品过程§3.5/3.6、ArtifactRevision/DecisionAndOutcome与AC04/06的效果判断首片。保存和读回不证明因果正确，不修改方案采纳、实际执行或经营观察。本批实际检查和独立结论见[结果记录](../openspec/changes/effect-assessments-v01/results.md)。

## 版本与准确业务关联

复用原ArtifactStore及publish_artifact/read_artifact，不新增判断版本系统或Runtime。judgment的可选content.effect保存准确plan、choiceId、execution id/revision、observation id/revision、实际scope、evidenceConnection、competingExplanations和limitations；结论沿summary，未知沿unknowns。证据另沿原ref/hash数组保存。未成熟/缺资料可以形成“尚不能判断”的有限结论，不强制评分或某种归因方法。

Host核准确执行/观察及原方案/选择属于同一关联，观察所引用的execution必须与判断引用一致；不依据文字相似度推范围，不取latest代替准版本。一个效果事项的plan/choice不能改挂，也不能降为普通成果绕过资格。显式修订沿expectedVersion、requestId、reason和supersedes追加，旧判断可准确读回；这不代表已实现反证自动修正或依赖建议重评。

## 当前资格与正文保护

只有当前main可读写效果判断。每次保存或读回完整重验原执行、观察、原方案、选择/负责人陈述和补充证据；核对期间binding/目标/epoch变化则拒绝。原选中方案即使已有新建议，仍按原准确版本核验，不搬移已发生事实。

来源新代先只给安全元数据；同目标准确旧效果可完整重验后追加当前资格回执，原内容/epoch不改。失败追加unavailable使旧PASS失效；底层执行/观察失权也阻断派生效果正文。资格表增量追加并有查询索引，不把历史读取当长期授权。普通ArtifactStore.read对普通成果的原跨epoch限制、readForOutcome仅同目标准plan的边界保持。

## 工作台和职责

Host专用effectAssessments投影只给当前合格正文或安全索引；效果判断从一般artifactRevisions投影分开，避免把局部归因写成整个委托当前判断。沿已确认“结果与学习”原归因槽按准确choice/plan显示，旧版本与证据联系/竞争解释/限制/未知按需展开。失权不借旧payload字段回放正文；经验仍为空态，不增加签收、表单或经营者写动作。

NativeResearchPort v0.1与owner/profile不变，官方Harness0.2.2-rc.3、superagent固定提交8c32a9dc5d72c033816c6a8110b37f40cf94fba4及原锁未改。Host管身份、版本、准确关联、权限与持久化；Agent自主评价证据、形成有范围的结论；复用SDK原会话/工具循环，不增加模型循环、调度器或分析流水线。
