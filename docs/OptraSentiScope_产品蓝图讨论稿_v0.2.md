## 2. 产品定位及与 OptraCall 的关系

### 2.1 产品定位

**OptraSentiScope 是面向企业经营目标的自主决策智能产品（Autonomous Decision Intelligence）。它利用企业积累的业务上下文，持续发现问题、风险和机会，自主开展动态探索与并行研究，提出有依据的决策方案，并通过实际结果持续修正业务认识与策略。**

核心变化是从 OptraCall 的分析与决策 AI 助手，发展到围绕经营目标持续工作的自主决策智能。自主性覆盖问题发现、研究组织、方法选择、方案比较和结果学习；当前经营行动由负责人决定并执行。

### 2.2 两个产品的关系

| 方面 | 已确认方向 |
| --- | --- |
| 产品关系 | SentiScope 是独立的新产品；OptraCall 保持现有方向 |
| 工程与能力 | SentiScope 继承 Call 的工程规范和可复用能力，围绕自身定位重新设计 |
| 业务理解 | Call 通过 Case—项目—任务的实际工作，积累 SAP、RAP、四库／双库等业务上下文与经验，供 SentiScope 继承使用 |
| 开发顺序 | 先建设 Call 并积累业务能力与上下文，再推进 SentiScope |
| 企业导入顺序 | 企业先使用 Call，形成一定业务积累后，再使用 SentiScope |

Call 自身持续交付分析与决策价值，业务积累伴随日常工作产生。Call 的 Agent 同样自主执行；两者的差异在于 SentiScope 将自主工作扩展到经营目标下的持续问题发现、研究推进与学习。

“具备一定积累”需要体现为对具体业务范围的理解和实际可用性。Case 数量、资料规模或使用时长不能单独证明具备这一条件。首个POC使用已确认的合成Call上下文；真实Call积累的正确采用、更新与接入证据仍需验证。

## 3. 用户与持续经营目标委托

### 3.1 首要用户

首先聚焦承担明确经营目标的业务负责人，企业负责人也可以使用。用户能够判断方案价值、作出经营取舍，并获得或协调实际执行与结果反馈。首个POC具体聚焦成人服饰品牌的电商业务负责人，经营范围为一个品牌的一个主要平台／店铺。

### 3.2 持续委托的内容

以具体经营目标为持续委托单位。用户明确希望达成的结果和必要边界，Agent 自主判断哪些事情值得研究、如何推进，以及何时交付当前判断。

| 内容 | 应明确的业务含义 |
| --- | --- |
| 经营目标 | 业务对象与范围、预期变化、评价周期和成功标准；定量目标关联准确指标口径 |
| 经营约束 | 必须守住的底线、资源限制、不可接受的影响，以及目标冲突时的取舍优先级 |
| 研究授权 | 可使用的资料与能力、研究资源和成本边界、研究成果保存及结果跟踪范围 |
| 持续安排 | 委托有效范围、汇总与提醒要求，以及调整、暂停、结束和复盘条件 |

经营预算与研究预算分别表达。允许研究怎样分配经营预算，不自动包含实际支配该预算的权限。

目标设定优先复用 Call 中适用的口径、背景、历史判断和已知约束，减少重复解释和维护。重要歧义集中澄清；缺少的信息按实际情况保留，不能补造目标值或企业事实。具体入口、必需内容及确认交互仍待细化。

目标、约束及权限的实质调整由负责人决定；Agent 可以提出调整建议。委托可以调整、暂停和结束，具体有效期及收束安排在后续讨论中明确。

## 4. 自主范围与授权边界

当前自主范围限定为**研究、方案建议和结果跟踪**。调价、营销投放、资源投入等实际经营动作，由负责人决定和执行。有限授权的自动执行留作后续方向，不属于当前产品范围。

在已明确的目标、约束、权限和资源范围内，Agent 可以持续自主查阅材料、计算、核验、调整研究优先级、开展并行研究、保存研究成果和跟踪结果。

新增假设、分析维度或子研究属于范围内的普通工作，无需逐项审批。目标改变、约束放宽、资料使用范围扩大、额外费用或新的外部影响，需要对应决定或授权。联系客户或同事、购买资料、对外披露信息等研究活动，也须有相应授权。

业务背景可以继承，历史授权需核对当前适用范围。用户未回复时，请求保持待定，不能将沉默当成同意；不依赖该决定的获准研究继续推进。

职责沿用四点工程与产品原则：Host 管环境，Agent 自主执行，优先复用已获准第三方 SDK 的已有能力，减少人的操作。Host 提供上下文、权限、资源、持久化与可观察记录；Agent 自主进行专业研究与纠错。第三方 SDK 保持官方原包，采用与版本升级按用户授权及工程规范执行，具体技术选型未定。

## 5. 用户介入、汇总与提醒

### 5.1 用户介入原则

负责人掌握经营取舍，SentiScope 在既定范围内持续研究。重要发现可以告知，需要负责人判断的事项才等待答复。

| 处理方式 | 典型事项 | 继续工作的原则 |
| --- | --- | --- |
| 持续自主完成 | 查阅已授权资料、形成和淘汰假设、动态探索、并行研究、复算反证、比较方案及结果跟踪 | 自主调整方法、优先级和研究深度 |
| 主动告知，无需回复 | 重要发现、明显的判断变化、风险上升或值得考虑的新方案 | 说明影响、依据和未知，继续获准研究 |
| 集中澄清关键缺口 | 无法从现有材料确定，且会实质影响判断的业务事实、目标含义或约束冲突 | 先自主核对，仍无法解决时集中询问；受影响判断待定，其他研究继续 |
| 负责人决定 | 方案采纳、经营行动、目标或约束调整、新授权及额外资源 | 提供选择和影响说明；经营行动由负责人执行 |

Agent 可以自主归纳和修订研究认识；涉及正式指标口径、企业规则或既定约束的改变，提交对应负责人决定。用户无需逐条审批研究记录或候选经验。

### 5.2 提醒的判断依据

日常以定期汇总为主，重大紧急事项即时提醒，关键取舍集中询问。

是否即时提醒，围绕以下问题判断：**等到下一次汇总，是否会错过对经营目标有实质影响、且需要负责人关注或取舍的窗口？**

| 维度 | 判断依据 |
| --- | --- |
| 重要性 | 对目标、经营底线、潜在损失或可争取收益的影响，以及范围、持续时间和可逆性 |
| 紧急性 | 最迟关注或决定的时间；考虑准备时间后，等待是否使风险扩大、机会消失或选择减少 |
| 证据把握程度 | 已观察事实、推断与未知，来源可靠性，以及仍需核验的内容 |

重要且紧急的事项即时提醒；重要但可以等待的事项进入最近一次汇总；时间紧但影响有限的事项在授权内核查并通常进入汇总；其余线索按研究价值推进或暂缓。

有具体迹象、潜在后果严重且等待可能失去应对时间的风险，可以先提醒并明确未核实部分。证据把握程度影响核验力度和表达方式，不能使高后果风险仅因不确定而被忽略。

### 5.3 减少打扰

- 同一事项的多个指标、材料与并行发现合并表达。
- 新证据改变结论、影响明显扩大、窗口缩短或处置条件失效时再提醒；重复发现留在研究记录中。
- 在时间窗口允许时，先完成可自主进行的口径、数据延迟和重复信息核查。
- 询问集中说明：需要决定什么、有哪些选择、何时需要决定，以及暂不决定的影响。
- 汇总围绕目标进展、最值得关注的问题／风险／机会和待决事项组织，完整过程按需查看。
- 即时提醒说明：发生什么、为何影响目标、何时需要关注、依据与未知、需要负责人做什么。

提醒尺度可先根据目标、业务底线和历史积累提出建议，再由负责人校准关键部分。通用频率、渠道、等级和调整方式仍待确定；首个POC的重大修订标准已在第12节明确，分时资料快照不等于日常汇总频率。

## 6. 自主研究、动态探索与收敛

### 6.1 识别研究问题

研究问题可以来自目标偏差、风险前兆、潜在机会、证据矛盾和影响方案选择的关键未知。目标暂时达成时，仍可关注未来风险和未利用的机会。

每个问题至少能说明：与哪个目标有关、为什么值得研究、什么证据可能改变判断。研究价值结合影响、时间窗口、已有依据与取得新信息的成本判断。

### 6.2 动态扩展方向

Agent 根据证据自主扩展业务对象、时间、维度或作用机制，切换适当资料和方法，提出竞争解释、寻找反证，并修正问题本身。重复方向可以合并，薄弱或低价值方向可以降级、停止或暂缓。

这些活动可以穿插、重复和并行，由 Agent 自主组织。Host 不规定固定研究步骤、轮次或假设数量。

### 6.3 并行研究

按互补价值组织并行：不同解释、不同证据来源、不同方法，或对关键判断进行独立反证与复核。各分支共享必要目标、口径、范围和约束，并明确自己解决的问题；需要独立核验时，先形成独立结果，再对照主结论。

汇总检查证据质量、适用条件、共用来源及分歧。多个 Agent 的相似结论不按多数票认定正确。分支可随证据增补、合并和停止，始终遵守既定资源与授权边界。

### 6.4 收敛与停止

当前研究问题是展开和收敛的单位，经营目标是持续委托的单位。

| 情况 | 处理原则 |
| --- | --- |
| 关键判断有可追溯依据，主要替代解释经过相称检验，剩余未知暂不影响当前取舍 | 收敛本轮，交付判断和方案 |
| 新线索可能改变方案排序、揭示重要风险或明确适用条件 | 继续有针对性的探索 |
| 新信息价值有限，研究成本或等待代价更高 | 停止或暂缓相关方向，说明理由 |
| 缺少关键材料、权限或资源，无法完成必要验证 | 保留未知，交付有限结果或暂停受影响研究 |
| 决策窗口将关闭，但研究未完成 | 及时提供当前依据、选择及不确定性，由负责人取舍 |

资源耗尽、材料不足或期限到达不能证明结论成立。结束某项研究不自动结束持续委托。每次收敛说明当前判断、依据、剩余未知和重新研究的触发条件；没有实质变化时，避免重复开展相同研究。

## 7. 研究结论与决策方案的可靠性

### 7.1 证据、推理与方案分别检查

可靠性原则是：**结论强度与证据相称，决策方案随关键前提变化而调整。**

- 重要判断可回到准确数据、原文、版本和时间；重复转述按其原始依据识别。
- 核对业务对象、期间、粒度、口径、条件与当前适用性。
- 关键数值核对输入、单位、公式和中间结果；重大取舍所依赖的计算做相称独立复算。
- 实测数据、他人陈述、历史经验、模型推断和情景假设分别表达。
- 计算核验、机制解释、因果判断与方案评价分别检查，判断范围和强度与所具备的依据相符。

### 7.2 反证审查

围绕“哪些前提不成立，建议就必须改变”寻找竞争解释、反例、遗漏条件和不利结果。审查强度结合潜在影响、可逆性、证据薄弱程度和决策窗口确定。

关键前提被否定时修正判断或调整方案排序；依据不足时形成条件建议、补证建议或暂不行动的选择；未解分歧保留对应的不同解释与选择。核验与修订在授权内自主推进。

### 7.3 并行分歧处理

| 分歧来源 | 处理原则 |
| --- | --- |
| 数据、版本或口径不同 | 查明差异，统一可比条件后重算，或分别保留适用范围 |
| 方法、假设或适用条件不同 | 检查前提及结论对条件变化的敏感性 |
| 证据冲突或关键资料不足 | 继续核验；无法解决时保留未知和竞争解释 |
| 目标优先级、风险偏好或资源取舍不同 | 解释选择及影响，由负责人决定 |

### 7.4 方案与不确定性表达

重要方案说明服务目标、证据、关键假设、约束、备选及代价，以及哪些情况需要重评。备选可以包含维持现状、补充信息或延后行动。

表达时区分已核对的事实和计算、得到支持或待验证的解释、依赖假设的预测、未解分歧及证据不足。说明剩余未知是否可能改变推荐，以及最值得补充的依据。概率、区间或置信程度须有估计依据和适用条件，不以模型自信代替证据。

每次重要方案应能回答：现在为什么值得这样选择、什么可能使它失效、下一步应观察什么。修订保留此前判断、反证、失败和未解决问题。

## 8. 实际结果跟踪

重要方案提出时，留下当前基线、预期变化、观察窗口和可能推翻判断的条件。目标、口径或执行安排发生变化时保留修订依据，避免事后重写成功标准。

| 跟踪内容 | 应确认的事实 |
| --- | --- |
| 负责人选择 | 采纳、调整、拒绝或暂缓什么，理由是什么 |
| 实际执行 | 开始时间、覆盖对象、执行程度及中途调整 |
| 观察结果 | 指标及业务现象的变化，数据完整性、口径和观察时点 |
| 效果判断 | 与策略的关系、外部因素和竞争解释 |
| 后续认识 | 哪些判断得到支持、被削弱或仍然未知，策略适用于什么条件 |

建议、采纳、实际执行、观察结果和效果归因分别记录。尚未执行、观察窗口未到或资料缺失均保留实际状态；实际改善也需核验其与策略的关系。

优先从获准业务记录和 Call 既有反馈获取信息，仅在缺少影响判断的关键事实时集中询问，不要求负责人重复填报系统已有资料。

## 9. 持续学习与业务假设、策略修正

持续学习应实际改善下一次的背景理解、前提检查和策略比较，并能指出新证据改变了哪项判断。

业务假设表达有范围的机制或解释；新证据可以增强、限制、削弱或推翻它，保留原判断及变化原因。策略表达在特定目标、资源和条件下考虑采取的做法，评价时同时检查实际执行、业务环境和原有假设。

效果不佳可能来自执行不足、外部变化、机制判断错误或策略不适合，应分别检查并形成相应修正。修正说明哪些结论和建议受影响、哪些暂不受影响，以及是否需要负责人重新取舍。

### 9.1 防止错误固化为长期经验

| 内容性质 | 保留和使用原则 |
| --- | --- |
| 工作记录 | 保存实际研究、选择、行动、结果及失败，支持回溯 |

进入可复用经验的依据来自业务观察、可靠资料或相称验证。同一结论反复出现在报告中不增加独立依据。用户收藏表示值得参考，不能据此认定专业正确。

Agent 在授权内完成归纳、核验、纠错和适用性检查，无需逐条经验审批。正式业务规则、目标约束或关键经营选择的改变，交对应负责人决定。
