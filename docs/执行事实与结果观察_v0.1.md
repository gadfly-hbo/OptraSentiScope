# 执行事实与结果观察 v0.1

2026-11-17，实现已确认产品过程§3.5、搭建规格DecisionAndOutcome与AC06。本批只补执行与观察、自动复查和真实投影；效果归因与经验复用另批。当前实际检查、最终身份与独立结论以[结果记录](../openspec/changes/outcomes-v01/results.md)为准，不以本文的接口说明代替验证。

## 事实与准确关联

选择、实际执行、经营观察、效果判断各自独立。采纳不创建执行，原生投递、打开页面和研究检查不创建经营观察，观察改善不创建归因。

`record_execution_fact`保存准确方案artifactId/version和choiceId、原选择范围快照、实际scope、asOf、已知startedAt/endedAt、执行程度与来源，状态分别为not_started/partial/completed/unknown。scope表示实际执行对象，选择scope表示原取舍，Host不根据文字相似度代作范围判断。没有记录不能据采纳推“已执行”，实际未知可明示缺口。

`record_result_observation`保存准确方案/选择/执行id/revision、观察scope、period、observedAt、baseline/measure/result/comparability，以及mature/immature/missing_data、gaps和unknowns。迟来的分期结果可以明确关联仍合格的旧执行修订，不换成最新执行；同一观察自身的修订则追加版本。实际时间不允许未来冒作已发生事实，观察期间不晚于获取时间。

记录采用不可变修订、expectedRevision CAS和requestId幂等。同一事实事项不能改挂另一选择或方案；技术重复不增加实质修订，旧内容、修订原因与准确关联保留。一个选择可以有多个不同范围/期间的事实事项，独立选择不混并。

## 来源、原话与当前资格

资料沿原SourceStore准确ref/hash读取。已有补充对话原话通过research_context.operatorStatements的安全messageId/时间定位，`read_operator_statement`按当前Host身份读原话；保存时保留statementIds及原话/时间，展示为负责人陈述、未经系统独立核实。无需新增填写表单或逐条签收。非未知的执行状态与实际观察需要资料或真实已保存原话；unknown/missing_data可以缺来源，但必须保存相应unknowns/gaps理由，不能补造事实。

`read_execution_fact`和`read_result_observation`每次按当前main运行绑定核对准原件、原选择、原话及资料；观察还核其准确执行修订。普通ArtifactStore.read原契约不变。结果专用readForOutcome只读取同目标的准确原plan，重新核其全部原资料当前资格；新版建议不会把旧结果搬到新版，缺失也不改latest。历史资料是否可读仍由SourceStore原cacheBody/allowHistorical授权决定。

来源epoch前进后，原记录内容/epoch保持，先只提供安全元数据。Agent可对准确旧执行/观察完整重验，成功后追加当前epoch资格回执，随后准许该正文读回、当前投影及安排复查；失败追加unavailable，旧PASS不继续授予当前投影。资格日志增量追加，不能把一次保存或历史回执当长期访问许可。跨目标、撤权、原版本不可读和异步核对期间资格变化继续拒绝正文，原件仍留存。

## 自动复查与生命周期

`arrange_outcome_review`引用准确execution/observation的kind/id/revision；Host从已重验原件绑定原方案，复用现有FollowupStore业务意图及Harness原生at或已获准source_event/可选reviewAt。Agent自主决定等待条件与复查时间，没有新增计时器、模型循环或周期催办。

到期后先读准确结果及当前资料，`record_followup_observation`只记录这次研究检查。需要新的经营观察时，Agent另调用record_result_observation，不能用调度回执或研究检查填充结果。当前结果修订已被替代时，旧复查不能冒作当前责任；新计划由Agent据变化安排。观察未成熟或缺资料不阻塞其他独立研究。

观察原本对应的execution修订和本次复查的当前执行上下文分开保存。arrange_outcome_review重验同事项最新执行并保存outcomeContext.execution；执行再次变化时，旧安排失效。Agent仍可为原观察重新安排核对，例如A范围的未成熟观察不会因为后来新增B范围执行就被改写到B；新安排带新的执行上下文，原观察的实际关联不动。Host只核版本与资格，不代Agent判断观察价值或要求负责人重新填报。

创建前提交creating、保存准确原生ID、未知不盲重建的原合同保持。暂停停止新增派发、保留未完成复查责任；创建期间迟到ID只用于核停，不抹掉同目标暂停责任。恢复核当前资格，按既有公开Session/Schedule恢复接缝继续。结束关闭未来工作；旧事实与失败保留，不将结束解释为目标达成或方案失败。
