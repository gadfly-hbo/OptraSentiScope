# 经营者取舍与持续跟进 v0.1

2026-11-17，已确认首版的待决事项切片。依据通用搭建规格 DecisionAndOutcome／NotificationIntent、AC05 和产品过程 §3.4；用户本轮授权开发。它承接成果版本与自主观察，不表示自动汇总、外发通知、执行／观察经营结果／归因或完整首版已完成。

## 事实与准确版本

主Agent用`propose_decision`关联准确的当前方案，保存事项id/revision、方案artifactId/version、目标/来源资格代、修订原因和关系；字段包括问题、选项及各自范围/代价/风险、推荐和依据、未知、暂不决定影响与独立研究下一步。内容与修订不可覆盖，expectedRevision比较当前版本，requestId精确幂等。只有主Agent有提问与解释工具，worker继续研究、交付成果。

`DecisionStore`是SentiScope的经营选择事实，不是官方Engine研究Decision、工单或另一个Runtime。Host绑定owner和委托、校验结构/权限/版本并持久化；是否真正需要经营者取舍、选项和业务意义由Agent判断。人的采纳不改变目标/权限/预算，不触发实际经营动作。

## 经营者路径与回应

经营者工作台的真实待决数→委托待决卡→查看推荐范围/代价/窗口及方案依据→一次知悉、采纳推荐范围、暂缓或一句话说明选择。沿已确认Demo的卡片和调整弹窗，无新导航、技术配置或逐条签收。查看方案依据按准确artifactId/version展开并定位；新版到达时保留正在查看的旧版卡片/依据标题、可见位置及用户展开状态，普通刷新不强制滚动。

知悉只保存acknowledgement，仍待决；沉默没有选择事实。按钮的明确采纳只作用于该选项完整范围；部分采纳/调整要保留明确范围。原始回应保存准确事项/方案版本、Host绑定身份、时间、原话和请求身份；普通补充对话不自动猜属于哪个事项，也不自动变成采纳。

一句话回应先保存原话，主Agent通过`read_decision`／`research_context`在当前资格下读回，`interpret_operator_response`必须引用已保存的responseId。解释可记录知悉、明确采纳/部分采纳/调整/拒绝/暂缓，含糊则说明待澄清；来源正文或Agent不能虚构人类输入。已经明确的按钮动作和范围不能被Agent扩大，typed知悉不能升为采纳。每份原话只能解释一次，后续人类补充作为新事实保留，不能覆盖原选择。

选择、原话、解释、原生派发和实际读取分别留证；选择不产生执行／效果记录。自然语言意图理解质量在本批没有真实模型验证，不能从合成解释机制通过推出语义正确率。

## 窗口与继续研究

事项保存提醒时间、最迟有效决定时间、执行期限及依据，均为有时区的准确时间，拒绝不可能日期与矛盾顺序。没有硬性截止时不补造时间，只说明依据和下一次复查安排。最迟决定时间已过，或只给出了执行期限且该期限已过，回应先保留；提醒/复查点经过不被当作硬截止。暂停期间回应同样保留；当前方案与资格仍成立、恢复active且Agent明确记录重新核对适用性的理由后，才能成为有效选择。结束不接受新选择，未解决事项带原因收束，不记为采纳或拒绝。

本批保存和展示窗口并提供Agent准确读回；自动汇总、站内自动提醒与外发为后续切片。本批仍复用已有原生周期Schedule和Agent自主观察安排；不另建窗口计时系统，不声称“字段已保存”即“已定时提醒”。

回应提交后由既有官方Engine接收仅含事项/回应准确ID的operator输入，使用既有assessment意图和主Session派发；每条回应使用独立技术输入线程，避免被另一项正在评估的事件阻挡，不据此新建研究工单。正文须经当前读回资格取得；Agent判断应关联原研究、忽略重复还是开启新问题。原生接纳/读回不表示已经处理完经营选择。

待决不接入成果观察的waiting门；未回复只让依赖取舍的研究部分等待，独立研究可继续。Host不替Agent规划研究步骤，不让经营者反复发“继续”。业务回应先提交，协调失败保留原事实；重启按原ID对账，既有claimed/unknown派发不盲重放。

## 历史、撤回与恢复

新方案或新事项修订不继承旧版选择，旧页面不能为新版本选择。Host保留原始历史；Agent的list只给安全元数据，准确正文读回和幂等重放均重新核原生binding、目标/来源资格及准确方案依据。撤权后不经旧待决、原话或摘要重放派生正文。

暂停保留事实而不自动生效，恢复重新核资格与窗口；结束保留关闭原因。正常重开保留SQLite事实，官方SDK合成链核对原话、选择和版本；本批没有新增OS崩溃恢复证明，原成果/观察冷恢复只按其原证据范围保留。
