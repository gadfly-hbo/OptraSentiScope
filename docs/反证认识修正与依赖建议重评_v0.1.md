# 反证认识修正与依赖建议重评 v0.1

2026-11-17，落实产品过程§3.2/3.6、ArtifactRevision/AC04/06/07/08的首个认识修正工程切片。本片只闭合同一委托内“证据触发→准确原判断读回→认识检查→显式依赖建议逐项重评→后续观察”；不形成条件经验、不做跨委托复用，不宣称AC07或完整首版完成。结果与证据见[OpenSpec记录](../openspec/changes/cognition-reassessment-v01/results.md)。

## 准确读回与显式支持

`ArtifactStore.reassessment` 是普通judgment/plan唯一新增的跨来源epoch安全读回路径。它必须持当前主Agent资格和同一目标，按准确artifactId/version完整重验原依据；成功返回原件、历史访问/当前使用资格和待重核状态，失败只返回安全元数据、限制与UNKNOWN。普通`read`仍拒绝跨epoch正文，effect判断仍走既有专用重核路径，不换latest。

`declare_support_dependency` 由Agent显式声明J→P业务支持：准确判断版本、准确建议版本、业务范围和依赖原因不可变保存，可按CAS修订并保留supportHistory。普通引用、共享资料、effect.plan的被评估关系不自动连边；Host只验证归属、版本与当前资格，不代作业务影响判断。

## 检查、逐项重评与恢复

`record_cognition_review` 保存触发事实、原判断、可选新判断版本、结论、变化、限制、未知和后续观察条件。维持/证据不足只留检查记录，不制造空判断版本。来源事件必须是已持久化的同委托事实；执行/观察触发走准确结果读回；followup触发必须已到期。

认识或当前适用性变化后，系统只从仍激活且建议版本仍最新的显式支持关系生成逐项重评责任。`record_plan_reassessment` 独立给出维持/调整/限缩/撤回/证据不足；目标建议或支持关系变化时旧结果只可保留归属并置superseded，不能关闭当前责任。重复请求幂等，Host重开后pending责任继续唤醒主Agent；局部UNKNOWN/blocked不影响无关建议或独立研究。

## 接线与边界

复用官方Engine/Harness主Agent工具循环、原生Session、Followup和Schedule；`research_context`暴露安全cognition投影与来源事件索引，`beforeWake`仍先做来源扫描，未新增Runtime、全局队列、计时器或通用图平台。工作台沿用“结果与学习”位置展示反证变化、待重评、逐项结果和后续条件；失权投影只保留准确索引，不回放旧正文。

NativeResearchPort v0.1、owner/profile、官方Harness 0.2.2-rc.3与superagent固定提交/原锁不变。计算OFF、Call DEFERRED；无真实模型、企业资料、生产访问、外部消息、部署或具体POC。旧选择、原方案、执行、观察和效果关联原字节保留，新建议不承接旧采纳或执行。
