# OptraSentiScope 通用首版搭建规格 v0.1

日期：2026-11-16（Asia/Shanghai）。状态：**搭建与UI审阅候选，尚未获用户对本规格和固定Demo的确认；未实施产品。**

## 1. 输入、目标与授权

输入为已确认的[产品首版范围与完整过程](通用产品首版范围与完整使用过程_v0.1.md)、[DSH架构v0.2](DSH_技术架构方案_v0.2.md)、[接入方案v0.1](Call只读接入与superagent源码消费方案_v0.1.md)、[首发运行方案v0.1](首发运行方案_v0.1.md)及[工程规范](engineering-workflow.md)。原始确认见[运行方案证据记录](首发运行方案_v0.1_确认与证据记录.md)。本轮交付规格及[关键交互Demo](prototypes/general-v0.1/index.html)，只允许文档和独立演示代码，不安装SDK或启动产品。

搭建目标是单企业专用常驻Host＋浏览器工作台，完整承担持续经营目标委托：建立与背景补全、自动信息接入、无消息自主研究、判断与方案、必要决定、结果跟踪、认识修正与后续复用，全程可调整／暂停／恢复／结束。

委托跨会话、研究问题及多次交付持续存在，浏览器不是运行权威。Agent的研究方法、顺序、工具组合、并行和收敛自主决定；本规格的体验与工程批次不构成固定分析阶段。

**Call只读接缝开发继续后排。** 先期可推进不依赖其实现的能力；完整首版CAP03仍保留真实Call复用未完成项。模拟合同／虚构资料／人工投递不等于Call已接通，不把阶段能力记为完整首版验收通过。

当前自主范围只含研究、建议与结果跟踪。经营动作由负责人决定并执行。已确认的产品／运行语义直接沿用；本稿提出的模块接线、数据合同、存储候选和具体交互供审核，尚未建立接口。

## 3. 模块与唯一权威

自有模块以TypeScript／Cordis插件接入方向组织，复用已确认官方底座；生产UI框架和具体存储驱动尚未选择，Demo原生JS不自动成为生产技术栈。

| 模块 | 权威及最小职责 | 不重复建设的边界 |
| --- | --- | --- |
| 产品工作台 | 展示投影、目标表达、决定、方案／依据／结果及生命周期入口 | 不以浏览器在线性控制委托运行，不直持模型／来源密钥 |
| 委托与资格 | SentiScope持有企业域＋委托、目标／约束／授权版本、资源与生命周期 | 不把原生Session／Goal当长期委托权威 |
| 统一运行接入 | Harness持有Agent／Session／inbox／turn／子Agent和原生历史；Host持有handle与代际 | 不建平行Runtime、会话循环、压缩器或全局业务队列 |
| 研究工单 | 采用后由官方Engine持有Trigger／Thread／Ticket／Assignment／Decision及订阅 | 不把自有任务列表变成第二套权威工单状态机 |
| 来源与证据 | 原来源持正式资产权威；SentiScope保存准确引用、版本、时间、资格、接收和内部因果关系 | 不以派生索引、重复报告或Agent产物代替原始证据 |
| 方案、反馈与学习 | SentiScope分别维护判断版本、负责人选择、执行、观察、归因、经验及变化依据 | 不合为单一“成功／完成”，不自动改正式业务规则 |
| 调度与提醒 | Harness Schedule管理到期和原生投递；SentiScope保存业务含义、关联ID及提醒理由 | 不新增计时器体系；回执不代表实际研究完成 |
| 计算与出口 | Host绑定全部文件／shell／terminal／jobs的执行世界、资源、资料和出口能力 | 计算环境不是第二Runtime；同用户目录权限不证明密钥隔离 |

产品业务事务库推荐以支持同步事务的SQLite作为候选，原件／产物使用受控文件库，Harness历史使用适用的官方持久化组合。具体驱动、目录、备份及恢复须核定；不凭候选声明运行持久性。Engine同步事务与自有report／note／epoch／投递关联遵循v0.2同事务要求，不能替换成异步事务回调。

## 4. 数据与接口语义

以下是待实现的最小业务合同，非现有HTTP路径／SDK接口声明。实际类型、协议及版本在实施前明确owner/profile、范围和兼容要求。

| 合同 | 必需语义 |
| --- | --- |
| DelegationCommand | 建立／调整／暂停／恢复／结束；调用身份及owner由Host绑定，带当前版本，重复请求对账，不伪造Call身份 |
| SourceAccess | 来源发现、准确版本读取、当前资格重验；内容身份与准入分开，缺失／hash冲突不回落latest；Call消费映射capabilities/list/readExact/checkCurrent但保持未接通 |
| IntakeReceipt | 来源事件ID、原件／准确引用、版本／hash、业务及获取／可知时间、资格和接收事实；可恢复持久化后才推进来源游标 |
| ResearchAdmission | 候选包含目标、事件、原报告和已关联工单（含已结束项）；由Agent决定已有影响与是否另建问题，Host只技术去重 |
| RunBinding | owner、当前委托／授权版本、Assignment、恢复epoch及native handle代际绑定；业务只取得受限Ref |
| ArtifactRevision | 判断／方案版本、原依据及反证、关键计算、假设、未知、失效和观察条件；旧版不可被新建议静默覆盖 |
| DecisionAndOutcome | 人的选择、执行事实、观察结果、效果判断各自有时间、范围、来源、对应方案版本；知悉不等于采纳 |
| EvidenceEligibility | 模型输入前核当前资格，含缓存／摘要／旧会话重放；历史回执非长期授权，失权正文不能直接续入模型 |
| NotificationIntent | 区分告知、需事实、需决定；真实窗口／选择／暂不决定影响、收件与渠道范围、合并理由 |

请求接收、资格通过、实际派发、原生接纳、实际读取、问题解决分别留证。模型、网络、会话和计算调用在事务提交后进行；提交前核当前绑定，崩溃／重复回调复用已有意图并核回执，不盲重发。

原始故障和差量记录增量追加，完整汇总仅收尾生成一次。后续长流检查应计量累计写入量、完整读回、写入失败及异常退出，避免逐事件重写完整历史。该要求是环境可靠性，不强制Agent使用固定分析脚本。

## 5. 状态与关键异常

### 5.1 状态层次

| 层次 | 显示及解释 |
| --- | --- |
| 委托生命周期 | 待建立、有效、正在暂停、已暂停、正在恢复、正在结束、已结束；研究等待和故障不自动改变为用户暂停 |
| 研究／等待 | 正在研究、有理由观察、局部待资料／决定／授权／资源、技术故障、UNKNOWN；多事项可并行处于不同状态 |
| 来源事实 | 未接通、可用、陈旧、撤回、资格未知、准确版本缺失；Call后排明确显示待接入 |
| 运行控制事实 | 已关新派发、取消已请求、在途未停、已停止、清理失败隔离、迟到结果；不以idle或命令成功冒充全部停止 |

自然语言目标及必要边界已完整、有有效资料／资源授权即可启动，不二次审批整表；关键缺口集中询问，仅阻塞依赖部分。没有新消息仍可继续旧资料研究、反证、查询及跟踪，低价值方向收敛并留复查时点／条件。

### 5.2 生命周期及竞态

- 调整以新版本生效，受影响部分重评，撤权立即关闭相关资格；晚到结果保留旧绑定，不覆盖新目标。
- 暂停／结束先阻止新增派发，再通过原生接口停止并核对在途／子工作；停止事实未明前显示处理中。
- 默认暂停研究与专属主动采集／检查，其他委托共享来源可按其授权继续；待决项及真实窗口保留，暂停普通催办。
- 恢复核当前权限／资源、已有成果／回执、期间变化及空白；部分可继续即推进，失效范围单独等待，不要求用户逐个重启资源。
- 结束保留真实选择、执行、观察、失败及未知，未决注明收束原因；新消息不重开，继续工作采用关联新委托。
- failed后的真实恢复、事实补读note、旧held输入及原回执按v0.2分记；UNKNOWN先查产物与回执，不盲重放或换模型。
- 资料撤回涵盖缓存、历史摘要和会话恢复。必要时用原生新会话承接同一委托，只带获准内容；已发字节不可追回，轮询不承诺跨Host即时撤回。

## 6. 运行、计算与出口

沿首发运行方案：凭据只由Host解析，模型／浏览器不取得原始密钥；所有工具与子Agent遵守同一资格边界。计算域默认无网、无Host密钥／数据根／控制socket和密钥环境变量；只挂获准输入与结果目录及资源配额，文件／shell／terminal／jobs统一执行世界。

候选隔离载体和具体网络／进程边界尚待核对，不把SandboxMode、0600、工作目录名或子Agent身份当成完整隔离证明。优先复用官方能力，再以必要外层环境约束补齐已证实缺口，不能改官方实现。

模型输入、外部研究／连接器、提醒／人工导出、日志／监控／备份四类出口分别按授权管理；额外会话日志出口关闭。固定rc.3默认fetch可访问私网，后续接线必须落实工具及网络限制。首发具体入口、登录和管理面隔离另落实，不把SDK进程令牌直接当业务授权。

## 7. 工作台与Demo合同

界面名称为「经营者工作台」，品牌保留OptraSentiScope名称，复用OptraCall双圆环Logo及「持续做出更好的决策」slogan、亮暗品牌色与中性底。品牌来源版本、原资产哈希见[Demo说明](prototypes/general-v0.1/README.md)。呈现名称调整不改变负责人权限角色，也不引入Call数据接入。

Demo仅虚构内存状态，不进行联网、文件导入、模型调用、SDK或资料接入；刷新／重置恢复示例，不保存工作数据。主题也不作为持久化验证。全局展示“交互演示／虚构资料／仅内存状态”，Call始终待接入。情境推进放独立可折叠演示区，不成为产品普通用户的必做步骤。

默认总览和委托进展，当前判断／变化、研究问题、后续安排及源覆盖先于对话。按需查看方案／依据、待决、结果学习和补充对话。界面不要求SDK身份、技术profile、工单ID或机器配置。

| Demo路径 | 对应标准 | 可审阅结果 |
| --- | --- | --- |
| U01 一句话建立／空态 | AC01 | 目标加可选边界，非空完整示例一次建立；不把虚构背景说成Call读取 |
| U02 进展／离开返回／推进演示时间 | AC02 | 看见模拟研究变化、观察理由及下次条件；只证明交互，不证明关页后真运行 |
| U03 新信息／重复投递 | AC03 | 已有研究变化及独立新问题，重复不重复建单；原始及内部产物区分 |
| U04 依据与有限判断 | AC04 | 原文、版本、时间、假设、未知及主要取舍可展开 |
| U05 决策及未回复 | AC05 | 知悉仍待决，选择含影响／窗口；采纳关联版本，其他研究继续 |
| U06 结果事实 | AC06 | 采纳、执行、观察、归因独立，模拟反馈只更新相应事实 |
