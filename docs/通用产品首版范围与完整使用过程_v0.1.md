# OptraSentiScope 通用产品首版范围与完整使用过程 v0.1

确认与固化日期：2026-11-16（Asia/Shanghai）。状态：用户已确认的产品设计基线，尚未实现或运行验证。

## 1. 定位、依据与最小完整闭环

首版是围绕持续经营目标，能够自主研究、交付判断、跟踪结果并修正认识的负责人工作台。首版缩减接入广度和管理复杂度，保留完整使用过程。

产品定位与职责承接[蓝图 v0.4](OptraSentiScope_产品蓝图讨论稿_v0.4.md)，技术分工承接[DSH 技术架构 v0.2](DSH_技术架构方案_v0.2.md)，工程约束沿用[工程规范](engineering-workflow.md)。用户逐项确认、原始来源和设计复核关系见[确认与复核记录](通用产品首版_v0.1_确认与复核记录.md)。既有文档中的“下一步”“尚未确认”保留其记录时点含义，本稿不追溯修改历史。

最小完整闭环：

**建立委托与边界 → 复用 Call 背景、持续获取信息 → 自主研究 → 交付判断与方案 → 负责人作必要取舍并执行经营行动 → 跟踪执行及结果 → 修正判断、形成有条件经验 → 继续研究。**

调整、暂停、恢复和结束贯穿全程。上述是使用与价值关系，研究方法、顺序和并行安排由 Agent 自主决定。当前 Agent 自主范围是研究、方案建议和结果跟踪；实际经营行动由负责人决定并执行。

委托是持续跟进的长期工作对象，对话是补充信息、查看解释和作决定的入口。在运行环境、授权与资源有效时，负责人关闭页面、不再发消息，Agent 仍应推进；一次运行、一个工单或一份报告完成，不自动结束委托。

闭环不要求每次都证明方案有效。结果可以是改善、无效或仍未知，但必须说明依据、限制与后续安排。首版必须具备完整跟踪和修正能力，方案交付后继续承担有效委托的跟进责任。

## 2. 产品入口与日常使用

| 入口 | 默认提供的内容 |
| --- | --- |
| 委托总览，日常主入口 | 重要变化、新发现、待决定事项、各项目标和委托状态、最近有效跟进时间 |
| 具体委托空间 | 当前判断、当前研究重点及其与目标的关系、方案、结果、等待事项和后续安排；可在委托内对话 |
| 汇总与提醒 | 值得关注的变化或取舍，打开后直达对应委托或事项 |
| Call 关联入口 | 从已有业务背景带入上下文；Call 端额外快捷入口后置，必要资产复用仍属首版 |

首页兼顾自主研究带来的重要发现和待决事项。仅有一项委托时可以直接展开，减少跳转。对话用于追问依据、纠正事实、补充材料及表达决定；当前判断、方案和结果由系统持续整理。

首发客户端、部署位置和具体通知渠道尚未确定；入口组合确认不代表这些选择已经完成。

## 3. 完整使用过程

### 3.1 建立持续委托

采用“表达目标 → 自动复用背景和资料 → 集中澄清关键缺口 → 开始研究”的路径。负责人最少表达希望哪块业务发生什么变化，以及已有背景之外的必要边界。

必须明确的业务含义包括经营对象／范围、希望的结果、关键约束和当前研究授权；评价、资源和持续安排从适用背景及有效设置中补全。这些不是逐项必填表单。系统整理可查看、可修改的委托摘要，显示研究什么、怎样评价、守住什么、能用什么以及如何跟进。

Call 复用按当前企业、业务对象、期间、来源版本及权限核对，优先读取正式口径、已知约束、业务事实、历史研究与执行结果、资料入口。区分目标、事实、假设和经验；历史目标不自动成为新目标，历史授权核对当前有效性。来源更新后自主评估影响，历史判断仍关联当时版本，保留正式来源权威。

必要连接器、凭据和资源上限由管理者在相应授权内配置。Agent 在当前授权内查阅历史资料、选择相关内部和外部来源、建立订阅或检查安排；共享采集优先复用，人工投递作为补充。页面显示实际覆盖、新鲜度及尚未接通的来源。

只有自主核对后仍不能解决、且实质影响目标、边界、权限或当前关键判断的缺口才询问负责人。包括范围歧义、重要口径或周期、约束冲突、新授权／费用／外部影响、无法核实的关键事实。集中说明为何需要及答案的影响。

信息和授权完整即可开始，不再要求确认整张表。目标方向明确而目标值尚缺时，可以开展获准的现状研究；依赖该值的评价等待明确，不能补造数字或企业事实。缺口仅阻塞依赖部分，其他获准研究继续。经营预算与研究预算分别表达，研究如何使用经营预算不授予实际支配权限。

### 3.2 持续自主研究及事件处理

无新消息时，Agent 继续深挖已有资料、寻找遗漏维度／异常／机会／风险、比较竞争解释、寻找反证、核验计算、主动查询获准来源、跟踪执行与观察窗口。研究按目标影响、窗口、可能改变判断的程度和成本排序，可以扩展、并行、合并、停止或暂缓。

有价值的方向收敛后，可以进入有理由的观察状态，留下当前判断、剩余未知、下次检查时点或重新研究条件。届时自主跟进，无需负责人再发“继续”。持续负责包括研究、核查和观察，不要求模型持续消耗资源，不以穷尽所有可能维度为通用交付门槛。

| 新信息的影响 | 处理 |
| --- | --- |
| 补充、支持或反驳正在研究的问题 | 进入已有研究，核查受影响的依据、计算和判断 |
| 暴露尚未覆盖的独立问题 | 在委托范围内新建研究工单，关联来源与相关研究，由 Agent 安排优先级 |
| 实质影响已经完成的研究 | 建立关联旧工单和成果的后续研究事项，保留原判断和修订原因 |
| 重复信息或暂未改变判断 | 保留来源及必要核对记录，通常无需单独提醒 |

同一信息可以同时影响已有研究并暴露新问题。保持 v0.2 的工单扇出和委托研判双路含义：Host 处理身份、权限及确定性重复投递，Agent 判断业务价值、归属和是否另建工单。投递、已读及存在工单不代表问题已解决。

工单承接值得独立跟踪的问题，普通假设、计算或每条消息不必各建一单。已结束工单不因自动消息重开，已结束委托不因新资料复活。资料保留原件或准确引用、版本、业务时间、获取／可知时间及权限。Agent 输出和计算产物保留内部来源及因果关系，不能当成独立外部证据或无限唤醒源。

### 3.3 收敛、交付及查看进展

关键依据可追溯、主要替代解释经过相称核验、剩余未知暂不影响取舍时，收敛当前问题并交付。新线索可能改变选择时继续针对性研究；新增价值低于成本时停止或暂缓该方向；缺关键材料或窗口临近时交付有限判断、选择和未知。预算耗尽或期限到达不证明判断成立。

委托页默认显示当前判断与重要变化、正在研究的重点和已取得结果、后续跟进与等待事项、信息覆盖与运行情况。分别呈现资料更新时间、研究进展与经营结果。开放研究不显示无依据的完成百分比。

重要判断可展开至支持／反对依据、原文或数据版本及时间、关键计算与核验结果、历次判断变化。展示可核对的行动、结果和取舍理由，完整记录按需查看。

### 3.4 汇总、提醒与负责人介入

| 类型 | 典型内容与继续方式 |
| --- | --- |
| 自主处理 | 普通读取、研究方向调整、反证、计算纠错；不等回复，重要结果进入汇总 |
| 只需告知 | 重要发现、判断变化、风险上升或机会；说明影响、依据和未知，继续研究 |
| 需补关键事实 | 自查后仍有影响判断的事实缺口；仅相关判断待定 |
| 必须决定 | 方案采纳、经营取舍、目标／底线调整、正式口径变更、新授权与额外资源；等待对应负责人决定 |

研究结论由 Agent 核验修正，负责人决定经营取舍。提出备选可先告知，确实需要选择、投入资源或经营行动时形成待决事项。

默认每个工作日形成简短汇总，优先沿用有效偏好，允许调整；多委托可合并，按需阅读，无需逐条签收。没有实质变化时保留简短检查状态，默认不额外推送空汇总。汇总频率不限制研究节奏。

同一问题的多指标、多来源及并行发现合并为持续事项，再提醒突出变化。独立经营选择、期限或授权范围分别保留清楚的待决项，可放在同一汇总中。即时提醒判断等待下一次汇总是否会失去重要关注或决策时间；有具体迹象、后果严重的风险可先提醒，标明未核实部分并继续核查。

待决项说明决定什么、选择及代价、推荐和依据／未知、何时需要决定、暂不决定的影响及 Agent 后续动作。窗口来自事实或有依据的估计，预留实际执行准备时间；区分提醒时间、最迟有效决定时间和执行期限。无可靠截止依据时说明暂无硬性截止，给出复查安排。

负责人可一句话选择、调整、拒绝或暂缓，意思和范围明确即记录，无需重复确认整份方案。“收到”“已读”仅表示知悉。未回复时保持待决，继续不依赖决定的研究、补证、完善备选和跟踪窗口；仅在约定提醒点或实质变化时再提醒，不固定循环催批、不自动扩大通知对象或权限。窗口经过后记录选择变化，迟来回复先核对方案是否仍适用。

### 3.5 方案交付与结果跟踪

重要方案默认简短摘要，依据和详细记录按需展开。最少包含目标与建议、备选与资源／代价／风险、依据与未知、约束及失效条件、基线和预期变化／评价口径／观察窗口／来源／检查安排。预测有估计依据，不能估计的量保留未知；维持现状、补证或暂缓可作为有效选择。

| 跟踪内容 | 独立记录的事实 |
| --- | --- |
| 负责人选择 | 采纳、部分采纳、调整、拒绝或暂缓了哪个版本及什么范围 |
| 实际执行 | 开始时间、对象、程度及中途调整，注明系统记录或陈述来源 |
| 观察结果 | 指标或现象变化，观察是否成熟、资料是否完整可比 |
| 效果归因 | 与方案的证据联系、外部因素和仍成立的竞争解释 |

各项保存时间、范围、来源和方案版本，可同时呈现“已采纳、部分执行、观察改善、归因未知”。部分采纳／执行关联具体行动和对象，不把局部结果扩大至整份方案。缺记录时标明尚未确认。

交付时即安排跟进，优先读取获准业务记录和 Call 反馈，仅询问取不到的关键事实，无需重复填报。按实际执行、数据刷新和业务时滞检查；执行晚于计划、范围变化时更新当前观察安排并保留原评价标准与修订原因。观察未成熟时说明等待条件，其他研究继续。

### 3.6 判断修正与可复用经验

结果变化时，Agent 检查资料／口径／对象／观察期可比性、实际执行是否符合条件、外部及同期因素、原机制和策略适用性。方法按问题自主选择；前后变化提供线索，归因强度与相称证据一致，重要竞争解释未排除时保留归因未定。

重要修订说明新增证据、改变的判断、受影响建议和后续观察；重评依赖原认识的当前建议。Agent 自主修改研究判断和当前推荐，保留负责人当时看到／采纳的版本。新的经营取舍、目标约束或权限变化交对应负责人决定。

| 内容性质 | 保存及复用 |
| --- | --- |
| 工作记录 | 研究、选择、执行、结果、失败与未知，支持回溯 |
| 候选认识 | 当前解释或策略判断，明确证据和待验证部分 |
| 可复用经验 | 相称证据支持，携带适用范围、限制、反例及重新验证条件 |

复用依据来自业务观察、可靠资料或相称验证。重复报告不增加独立证据，收藏、采纳或满意不单独证明正确。失败区分执行不足、外部变化、判断错误、策略不适合或仍无法解释；未执行、未成熟和缺资料如实记录。

新反证出现时自主限制或撤回经验的当前适用性，并重评依赖建议，保留历史。跨委托／场景复用重新核对业务条件、时效和权限。正式口径与规则保留来源权威，对应变更由负责人决定；Call 全量双向同步及正式发布流程不据本稿假定已实现。

### 3.7 调整、暂停、恢复和结束

目标、范围、评价口径／周期／成功标准、底线／优先级、资源／费用、资料权限和外部影响的实质改变，以及暂停／恢复／结束，由负责人或对应授权人决定。普通研究调整由 Agent 自主完成。清楚的一句话即可生效，实质歧义才澄清。

| 操作 | 进行中研究、订阅、待决与成果的处理 |
| --- | --- |
| 调整 | 保留新旧版本、生效时间和来源。继续适用部分，停止或重评冲突部分；撤权立即阻止相关访问及新增工作。调整订阅及检查；不再相关的待决项注明原因而非记为拒绝；方案和历史保留并说明适用性 |
| 暂停 | 默认停止研究、专属主动采集／检查及触发；先阻止新增工作，再安全停止在途运行。共享来源按其他有效委托授权继续。保留待决项和真实期限，暂停本委托常规汇总及催办；用已有记录说明未关闭窗口。可明确选择只暂停某方向，或停研究但继续采集 |
| 恢复 | 明确指令或事先约定恢复时点后，核当前目标／权限／资源、已有产物／回执／未知、期间可获资料及空白；Agent 重评重点和过期窗口，系统恢复所需订阅、检查与运行资源。只问失效或需改变的部分，无需逐项重启 |
| 结束 | 默认负责人明确结束，或按已约定有效期／结束条件收束。阻止新增研究、安全停止在途工作，收束专属订阅／检查／提醒；以已有记录整理交付、实际执行／观察、失败和未知摘要，原因可选。未决项注明随结束收束，不记为采纳、拒绝或执行完成 |

等待资料、故障、观察期不自动等同暂停或结束；目标暂时达成、没有消息、长期未回复不自行结束。暂停指令生效与在途工作全部停止分别显示，未完成时显示正在暂停及影响。晚到结果标明原版本，只按当前资格引用，不能回退或复活当前状态。

恢复后提供继续事项、期间重要变化、仍受阻部分和下一步的摘要。不确定结果先核对，不盲重放；已结束工单需要新研究时关联后续事项。结束后新资料不自动重开，首版再次开展工作采用关联新委托，复用仍适用背景并核当前授权。

历史按既定保存和当前访问权限保留。暂停／结束不撤销实际经营行动，结束不等于目标达成。停止事实未核实不假报全部停止；环境故障、缺资料、业务待决、资源不足及未知分开显示，按 v0.2 的安全恢复与权限边界处理。

## 4. 首版必需能力

| 标识 | 能力 | 必需范围 |
| --- | --- | --- |
| CAP01 | 产品入口 | 总览、委托内对话、方案／依据查看、提醒直达；离开对话仍跟进 |
| CAP02 | 建立与生命周期 | 自动补全、关键澄清、版本化调整、暂停／恢复／结束；处理在途、共享来源、待决和历史 |
| CAP03 | Call 与信息接入 | 实际可用的适用资产复用、版本／权限与来源更新影响；有限获准内部／外部来源主动查取和更新订阅，人工投递补充，覆盖及缺口可见 |
| CAP04 | 持续研究与工单 | 有／无新消息持续研究、计算／反证／相称并行、既有问题更新及独立新工单、自主收敛和复查 |
| CAP05 | 依据与可靠性 | 来源、版本、时间、计算、假设与未知可核对；原始资料与研究产物分清，防循环证据和自激 |
| CAP06 | 汇总与介入 | 合并汇总、重要紧急提醒、真实窗口、告知／事实／决定分明；未回复独立研究继续 |
| CAP07 | 方案交付 | 目标建议、备选代价、依据未知、约束失效、基线观察安排及方案版本 |
| CAP08 | 结果与学习 | 采纳／执行／观察／归因分记，自主修正，有条件经验在后续研究复用并受反证约束 |
| CAP09 | 环境与保障 | 企业及委托授权隔离、受控模型输入与资料出口、资源上限、持久化、真实故障和安全恢复；额外会话日志出口关闭 |

Call 复用、自动信息流、持续自主研究、结果跟踪和学习修正不能因首版裁剪而删除。限定来源及资产种类，但不能用持续等人续聊、手工搬运资料或仅生成报告替代完整闭环。

通用机制处理委托、资料、研究、证据、方案、反馈和经验；行业指标、目标值、业务口径与策略条件保留在适用业务资产中，不固定成 Host 分析步骤。

## 5. 后置与当前范围之外

建议后置的能力广度和管理设施已随首版范围获确认：

- 全系统、全格式连接器目录及复杂采集平台；首版仍要打通选定必要来源。
- 复杂组织协作、审批、可视化工作流和人工工单编排；首版保留必要身份与授权边界。
- 独立知识运营后台、复杂实验／归因管理平台、定制报告体系；有依据的效果判断和条件化经验仍属首版。
- 全渠道通知、多端全面覆盖、Call 端额外快捷入口及全量双向同步；必要资产读取、引用和更新影响不后置。
- 大规模并发、复杂部署拓扑与运维平台；受控并行和基本保障仍属首版。

自动调价、投放、支出等经营执行不纳入当前产品范围。正式业务规则自动改写不是本次承诺，未来是否引入另行决定。

## 6. 基本成功标准

以下是后续可验证的通用预期，不是已运行结果，也不是具体 POC 的完整验证计划。

| 标识 | 可观察的成功标准 |
| --- | --- |
| AC01 | 信息和授权完整时一次目标表达即可启动，不重复录入 Call 背景或确认整张表 |
| AC02 | 负责人关闭页面且不再发消息，获准研究和到期检查仍继续；观察状态有理由及后续安排 |
| AC03 | 所选来源更新实际影响研究或形成新问题，重复投递不重复建单，内部产物不制造循环证据或无限唤醒 |
| AC04 | 重要判断可回到当时资料／计算，能交付有限结论并说明继续、暂缓或停止的理由 |
| AC05 | 负责人看清决定、窗口及不决定的影响；沉默不授权限，受影响部分等待，其他研究继续 |
| AC06 | 采纳不当作执行、改善不当作归因；缺资料、未执行、未成熟按事实呈现 |
| AC07 | 经验在适用后续研究中被调用，反证能限制／撤回适用性并重评依赖建议 |
| AC08 | 暂停／撤权／结束实际约束工作；恢复核资格与成果、不盲重放；失败、未知和历史不被覆盖 |

权限、资料出口、隔离、取消、真实恢复及当前版本采用必须在后续实现中实际验证，不能由界面文案或文档核对替代。负责人正常必需操作限于目标和边界表达、取不到的关键事实、必要授权与经营取舍及本人业务执行；查看、指定资料等自愿操作不变成每日任务。

## 7. 四原则设计复核

| 原则 | 设计落实与核对边界 |
| --- | --- |
| Host 管环境 | 管权限、凭据、资源、资料接入、持久化、原生运行控制和可观察记录；不固定专业研究步骤或代作业务价值判断 |
| Agent 自主执行 | 自主选问题、方法、工具、工单归属、优先级、并行、收敛及修订；范围内普通研究不逐项审批 |
| 优先复用获准 SDK 已有能力 | 保持 v0.2 的 Harness 原生能力和 superagent 候选 core 公开端口分工；SentiScope 补业务含义与必要适配，保持官方实现，不另造影子 Runtime／调度／工单状态机 |
| 减少人的操作 | 已有信息／授权完整即开始；普通读取、维度、工单、引用和技术身份不转嫁给人；生命周期一次表达、系统统一处理，必要管理配置不重复成为日常业务步骤 |

设计层面符合四原则。原范围独立复核要求显式补清的资料／产物防循环、受控出口及额外会话日志关闭、SDK 缩窄复用不能损害闭环三点，均已纳入被用户认可的首版文本。

若公开契约不能支持必需能力，撤回相应复用声明、保留缺口，并重新作范围或技术取舍，不能静默删减闭环、修改官方实现或建平行机制后仍宣称可交付。组件采用、精确版本及升级依相应授权进行。
